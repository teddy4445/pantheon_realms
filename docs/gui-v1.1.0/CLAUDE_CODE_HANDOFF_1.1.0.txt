4. COMPONENT GEOMETRY AND LIVE CONTENT

Frames: transparent overlays. Use CSS border-image with the per-file nineSlice values and NO fill, on a pointer-events:none pseudo-element. The proposed common source slices are 256 / 320 / 256 / 320 pixels (top/right/bottom/left) for the native 1536 x 1024 frames; reference CSS demonstrates them. Corner art remains intact as the middle runs scale. Use approximately 64 CSS pixels for the decorative border region and 40 pixels content padding; compact variants can reduce these after visual checking. The surface beneath is a separate inset layer. Never stretch a complete frame image indiscriminately across a tall narrow sidebar. On very small tooltips or rows, use a restrained CSS material border instead of oversized corner ornaments.

PNG alpha is real. Some file viewers show colored RGB hidden under zero alpha; this is not a brown fill. Load the PNG normally with alpha blending. Do not color-key it or regenerate a black-background copy. visibleBounds uses an alpha > 32 threshold only for layout measurement, never to modify pixel data.

Place the backing surface using each frame's surfaceInsetCssPx (top/right/bottom/left), measured from the straight-edge alpha at the 64px border display size. A generic 12px inset lets parchment protrude below some frames. Scale these inset values proportionally if the decorative border width changes. The interactive preview demonstrates the corrected backing alignment for all six themes.

Surfaces: opaque quiet images under live text. Use background-size:cover; they are not certified seamless tiles. Add an opaque or nearly opaque color backing when necessary for contrast. Stone is for command chrome, parchment for readable narrative, leather for equipment. Keep decorative texture subtle at display size.

Banner: use contain and the original aspect ratio. The safe central rectangle is recorded in metadata. Overlay the existing emblem and live faction name; do not bake either into a new banner. Provide selection check plus outline and an accessible name. No faction gets a different button geometry.

Book: use contain at its native 3:2 ratio. Text lives in the two safe page rectangles in the manifest. Do not place text across the spine. Long pages scroll within their area; at narrow widths switch to a single-page parchment layout instead of shrinking text. Journal, bestiary, spells and miracles can share the book material without losing their current categories.

Equipment figure: a quiet schematic under real sockets. Map positions to the existing slot enum. All real slots must exist, and all 30 backpack spaces must remain available. The concept's 20 visible backpack cells are only an illustration. Equipment and item bonuses stay live.

Button: a normal-state blank painted face. It includes transparent breathing space. The preview uses a 3:1 canvas ratio; its painted face occupies less than the full height. Keep labels within the painted face, provide a minimum 44px hit target, and allow wide labels to grow. For narrow icon controls, use a socket/material skin rather than squeezing a word button. Hover/focus/pressed/selected/unavailable are code states; do not tint an entire parent containing live text. The preview CSS isolates the painted face on a pseudo-element.

Socket: contain in a square, put the existing artifact/resource/creature image inside, quantities as live text outside or in a reserved corner. The visible square has transparent outer margin; the center is empty. Show selection and invalid/drop states with code overlays. Empty slots still expose a label on focus and inspection.

Recruitment art: opaque portrait scenery only. Place the selected existing creature rendering above it, with feet/contact at about (50%,86%) of the stage and scale according to the renderer's bounds. Preserve idle/reduced-motion behavior. Fit winged or tall units using their alpha bounds; do not crop their silhouette. Decorative architecture in these stages is scenery, not an extra town service or clickable building.

Merchant art: header illustration above the trade controls. The depicted merchants are anonymous decoration, not new named NPCs. Keep prices, stock, payment and output in live panels below it. Use the faction associated with the town.

6. TYPE, ACCESSIBILITY, MOTION AND SOUND

Reuse the game's font stacks (display title face, readable body/UI face); do not introduce remote font requests. The inspected tokens name Cinzel and EB Garamond with system fallbacks, but no bundled font files were found. The component proof uses Georgia/system-ui. Preserve reliable offline fallbacks; do not assume a named font is installed. If the implementation deliberately bundles a font, retain its license and validate packaged loading. Use approximately 16px body text at the 1080p baseline and the existing UI scaling settings. Keep exact quantities and costs readable. Parchment uses dark ink; dark stone/leather uses pale text. Verify text contrast at least 4.5:1 and UI/focus outlines at least 3:1, with existing high-contrast preferences preserved. Do not rely on color alone for ownership, availability or selection.

Focus trap and restoration for modals, semantic buttons/radio choices, Escape behavior, valid Enter confirmation and meaningful accessible names are required. Tooltips appear on focus as well as hover, with a proposed 250–400ms hover delay. Required information must not exist only in a tooltip. Keep controls reachable at small supported window sizes: stack content or scroll the body while keeping primary actions available.

Normal/hover/focus/pressed/selected/unavailable states belong in the shared components. Hover should brighten the rim; pressed can inset by 1px. Selected adds outline and check. Unavailable shows a reason and a lock/shape cue, not merely dimmed text. Respect prefers-reduced-motion and in-game settings. Suggested timing: 80–150ms buttons, 150–300ms panel/page changes, brief construction/slot success flashes. No long blocking cinematics for routine actions.

Reuse existing audio IDs and volume preferences from assets-runtime/audio/manifest.json for clicks and book open/close/page events. Play confirmation feedback after a successful command. Do not add sounds every time a quantity changes, on every hover, or on failed no-op actions. Visual feedback must work with audio disabled.
