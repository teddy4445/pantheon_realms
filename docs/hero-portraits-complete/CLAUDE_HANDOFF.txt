WHAT “FULL PORTRAIT” MEANS HERE
Large independent head-to-waist/thigh character illustration with transparent background, matching the existing game art. These are the .bust assets used by the game's dialogue system, not necessarily head-to-toe figures. They are not rigged models, map avatars, sprite strips or new animations. Preserve existing mounted map sprites and animation bindings.
Each new cutout was generated from that hero's actual square portrait. Face, hairstyle, clothing colors and signature equipment provide continuity. The original portrait icons and all existing bust files remain unchanged. Use the game art reference rather than assumptions about a famous or mythological name.

EXACT ID MAPPING — DO NOT GUESS FROM NAMES
Use the hero's portraitAssetId from content definitions and replace the trailing '.portrait' with '.bust'. This is already how packages/ui/src/assets/storyArt.ts::speakerBust works. Examples:
  hero.celtic.amergin.portrait -> hero.celtic.amergin.bust
  hero.greek.achilles.portrait -> hero.greek.achilles.bust
The hero definition ID may differ from the art ID slug. Many non-Greek heroes have a pantheon prefix in heroId; display names may contain accents. hero-map.json/CSV records the actual ID from buildCatalog(), not a guessed slug. Compare the current destination catalog against the delivery snapshot before merging if it has evolved.

COMPOSITION AND PERFORMANCE
Keep real alpha. Some viewers display colored RGB beneath transparent pixels; that is not an instruction to color-key or flatten. Never paint a matching background into the PNG. Use object-fit:contain and object-position:center bottom by default; do not use cover to crop off crowns or faces. Place the lower portrait edge behind an appropriate bottom panel or within its viewport, so a waist/thigh crop reads naturally.
The manifest supplies original dimensions and normalized visible alphaBox. Account for each silhouette; compare apparent face scale across heroes. Do not stretch everyone into a square. Responsive layouts can reduce or hide decorative busts only if the hero's identity remains visible in an accessible portrait/name treatment and gameplay controls remain available.
Names, costs, stats, tooltips, selection frames and buttons remain live UI. Do not extract them from concept screenshots. Provide alt text with the actual hero name for informative artwork, or empty alt when the adjacent live text already conveys it.
Lazy-load large portraits when the relevant panel/candidate becomes visible. Keep compact portrait icons for list rows. Avoid decoding all 89 full images on game startup. Cache the active pair and nearby candidates. These native PNGs are larger than the square icons; consult manifest bytes before choosing a preload strategy.
