CRITICAL USER REQUIREMENT — KEEP JOURNEYS BETWEEN DAYS
"When a hero moves over a few days to a location, keep the path so the user can continue without marking it again."

Persist the chosen destination PER HERO, scoped to match and controlling player. Do not keep it only in Recruitment or Adventure component useState.
Suggested presentation/session intent record:
  { version:1, matchId, playerId, heroId, target:{q,r}, targetSiteId?:string, status:"planned"|"paused"|"blocked" }
Keep the intended destination as authoritative intent. The remaining tile list is a cache only: re-quote from current position with current terrain, movement modifiers, known obstacles and movement points.
A mere hover is temporary preview and must not overwrite the saved destination. An explicit tile selection replaces that hero's intent. Starting or partially completing movement retains it.

Day boundary:
  End day must NOT delete destinations. Refill movement through current rules as usual.
  On the next human turn, re-quote selected hero's saved destination and redraw the remaining path with updated today/later styling and arrival number.
  Enable "Continue journey" (boot-arrow icon and tooltip with current shortcut). Pressing the existing continue_move binding (default Space) does the same.
  It moves only as far as this day's legal allowance and the existing encounter rules allow. It does not auto-end the day or auto-commit battle/dialog choices.
  Merely starting the new day does NOT move any hero. Player keeps control.
  Preserve routes for other heroes when selecting a different hero. Return to a hero restores their route.

Persistence:
  Include planned journeys in the save/session presentation payload, scoped per match/player/hero. Save/load, autosave, screen changes, town visits, menus, and switching heroes preserve them.
  Version the optional field; old saves with no journeys load as an empty dictionary.
  Use the existing save/session architecture; do not introduce a second unscoped localStorage store or leak other players' route plans.
  In multiplayer a private route plan is intent, not a rules mutation. Movement still uses authoritative validated commands. Do not bypass turn ownership, revision checks, or replays.

Invalidation and interruptions:
  Arrival: clear that hero's route after actual movement/interaction completes, not merely when an optimistic quote says arrival is possible.
  New explicit destination replaces only that hero's goal.
  Explicit Cancel journey clears only that hero's route. Ordinary right-click inspection/panning should not cancel it; change the present right-click clear behavior.
  No movement left: keep route, disabled Continue with "Continue next day".
  Combat, reward dialog, cutscene or other interruption: pause; if hero survives and goal remains meaningful, keep goal and re-quote after resolution.
  Temporarily blocked: retain destination, show blocked status and reason; do not silently clear or move via an unknown/unsafe alternate route. When legal again, Continue can resume.
  Path changed due to a newly visible blocker or movement modifier: recalculate legally with current information. Surface a meaningful reroute/encounter change before continuation; do not reveal hidden map data.
  Hero defeated/removed/transferred to another owner: remove or retire the old owner's intent. New match clears old match intents.
  Town/site destination: retain its identity when available and resolve its current accessible entrance/gate through game rules, not by walking into painted buildings.
  Teleport/recall: pause and re-quote from new position; do not replay stale path coordinates.
  Missing/invalid target after map changes: show route unavailable and offer cancel/reselect. Do not crash.
  Holding Space must not queue duplicate movement, and UI overlays/text inputs must keep their existing key guards.
