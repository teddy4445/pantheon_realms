PANTHEON REALMS · DEVELOPMENT PROPOSAL · 19 OCTOBER 2026

Single Battle
Land, siege and sea in one complete game mode.

Click Single Battle in New Game to open setup immediately. Choose a battle type, build both armies, configure the battlefield, deploy, and fight using the existing combat engine. No badge, introductory step or extra setup button. The mode ends with results and offers Rematch, Edit setup, Save preset, or New battle.

Open clickable setup previews · New Game picture · Land setup · Siege setup · Naval setup

Updated design: armies only, without heroes. Use distinct icons, concise labels and accessible tooltips; keep explanations in help rather than the main setup. The playable implementation is now available in version 1.8.0. Open the release guide, screenshots and installer link. The previews below preserve the approved design proposal.

Player experience

  1. Choose the encounter: open-field battle, town siege, ship boarding, or ship against sea creatures. Show a useful default setup immediately.
  2. Build each side: pantheon, human/AI/local second player, seven stack slots, creature form and quantity. Search/filter all implemented creatures; restrict sea-only creatures to compatible encounters.
  3. Army-only combat: no hero selector, portraits, levels, attributes, equipment, skills or hero spellbook. Creature statistics and innate abilities drive combat. Independent army or environment modifiers must be explicit; never create an invisible hero to supply bonuses.
  4. Shape the battlefield: select a supported terrain/layout, deterministic seed, obstacles, deployment areas, climate, and type-specific settings. Preview all movement restrictions.
  5. Validate and deploy: display actionable errors beside the offending setting; show footprints, blocked cells, attack sides and legal starting positions. Drag stacks, rotate large units, swap slots, undo/redo, or use automatic legal deployment.
  6. Fight and review: use current creature abilities, animations, damage previews and battle log. Results show casualties, survivors, damage, rounds and seed. Rematch restores the original setup, not the survivors.

Architecture

The existing packages/rules/src/systems/battle/factory.ts starts battles from adventure encounters, and the session owns campaign/adventure outcomes. Separate the reusable combat construction from those encounter and reward assumptions.

  1. Versioned definition: introduce SingleBattleSpec with schema version, content version, ID/name, seed, battle kind, both side definitions, terrain/deployment and siege/naval configuration. Keep authoring state distinct from runtime battle state.
  2. Pure validation: resolve IDs from the content catalog; reject unsupported abilities or layouts, non-finite numbers, quantities outside defined limits, overlapping footprints, illegal deck/water placement and unreachable deployment. Return structured field errors and warnings. Never trust imported JSON.
  3. Factory: extract shared stack/commander/board construction, then add createSingleBattle with null commanders and neutral commander bonuses on both sides. Prefer an explicit standalone context over fake towns, mission flags or invented adventure paths. Existing encounter callers retain current behavior.
  4. Session boundary: add an explicit standalone mode and result handling in packages/session. Reuse battle commands/events, initiative, AI and presentation. Do not apply adventure movement, town capture, campaign objectives or experience carryover when a standalone battle ends.
  5. UI: add the New Game tile in Setup.tsx; create a setup screen and creature picker; reuse creature portraits and faction emblems. Remove hero/loadout drawers entirely. Reuse Battle.tsx through a session-facing adapter rather than duplicating its controls.
  6. Persistence: add migrations and safe limits to the preset format; snapshot the normalized original spec for Rematch. Deterministic combat replay records commands with seed and content version, and rejects incompatible replays clearly.

Delivery sequence and acceptance gates

Planning estimate: 18–28 focused development days for one developer with existing assets and rules, plus any newly requested combat systems. These are effort estimates, not a delivery commitment. Each phase leaves a testable build.

Validation matrix

  • Seed/spec equality gives identical initial state; replaying identical commands yields identical results. Save/load preserves initiative, effects, walls, catapult phase, bridges and deck masks.
  • All six pantheons, commander-free armies, mixed roster, base/upgraded forms, seven full stacks, large creatures, each controller pairing, zero legal targets, final casualty, retreat/surrender and draw/stalemate handling.
  • Siege: every fortification level, destroyed gate, broken wall, keep target, defender selection, empty catapult target set, defender engine attack and legal deployment beside structures.
  • Naval: blocked bridge, flyers, swimmers, large footprints, sea-only monsters, ship versus ship and ship versus monsters. UI explains incompatible selections before launching.
  • UI at 1024×768, 1280×720, 1600×900 and high DPI; keyboard-only selection, readable focus, no color-only meaning, reduced motion and instant playback.
  • Rematch restores original armies/structures; editing a result produces a new setup; quitting standalone returns to its setup or menu; no campaign save or hero is changed.
  • Run unit and integration suites, targeted Playwright scenarios and packaged Windows smoke tests before generating the installer.

Visual direction

Keep the game's navy stone, antique gold and illustrated portraits. The new menu artwork combines a land confrontation, fortress and catapult, and ships with a sea creature. The setup uses a stable three-column composition: attacker, battlefield/rules, defender. There are no heroes. Creature portraits, tier and movement icons, quantity boxes and empty stack slots carry most of the information. Land, siege and naval tabs have distinct icons; reset, save and library use icon buttons with tooltips. The primary action is simply “Deploy”. Advanced settings live in drawers. Proposed previews use illustrative board geometry; implementation must render the exact engine geometry and actual content names.
